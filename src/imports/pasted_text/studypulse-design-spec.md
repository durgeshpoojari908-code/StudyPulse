Create a complete high-fidelity, production-quality UI/UX design system and interactive clickable prototype for a premium student productivity and academic progress app called:

STUDYPULSE

TAGLINE:
“Know Your Progress. Own Your Time.”

==================================================
1. PRODUCT PURPOSE
==================================================

StudyPulse is a personal academic productivity and progress-tracking app for college students.

It helps students:
- track academic progress
- manage any number of subjects
- plan daily study hours
- create personalized study schedules
- manage assignments and deadlines
- track actual study time
- monitor screen-time habits
- set academic goals
- understand weekly study insights
- improve consistency and productivity

The product must be generic and usable by students from ANY course, college, branch, or academic background.

Do NOT design the product specifically around Data Science, DSA, or any single degree.

==================================================
2. IMPORTANT PRODUCT RULE
==================================================

StudyPulse must NOT contain:
- AI chatbot
- AI assistant
- AI floating button
- AI chat screen
- AI icon
- AI-related feature

The app should help students through:
PLAN → STUDY → COMPLETE → TRACK → IMPROVE

==================================================
3. PRIMARY PLATFORM
==================================================

DESIGN MOBILE-FIRST.

The primary experience should be optimized for a modern smartphone.

Then create separate tablet and desktop layouts.

IMPORTANT:

Mobile and desktop must share the same visual design system but use layouts optimized for their respective screen sizes.

8. RESPONSIVE DESIGN RULES
==================================================

CREATE THREE DISTINCT RESPONSIVE EXPERIENCES:

A. MOBILE
B. TABLET
C. DESKTOP

------------------------------------------
MOBILE
------------------------------------------

Use:
- single-column content
- compact header
- full-width cards
- vertical scrolling
- thumb-friendly controls
- fixed bottom navigation
- optimized touch targets
- concise information hierarchy

IMPORTANT:
The mobile status bar/header must remain FIXED.

The following should NOT scroll away:
- status area
- top app header where applicable

The main app content should scroll underneath the fixed header.

The bottom navigation must also remain FIXED while the content scrolls.

The scrolling area must exist BETWEEN the fixed top/header area and fixed bottom navigation.

Do NOT make the phone status bar scroll together with the content.

------------------------------------------
DESKTOP
------------------------------------------

Do NOT use mobile bottom navigation.

Use:
- fixed left sidebar navigation
- top header
- multi-column dashboard
- 2–3 column card grids
- larger chart visualizations
- wider content area
- desktop-optimized spacing
- more information visible at once
